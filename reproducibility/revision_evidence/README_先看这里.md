# 4HDP返修结果核验材料

本材料包用于回应“公开仓库缺少支撑表2—表4的结果文件、汇总日志和失败样例”的意见。公开内容仅保留核验论文统计值所需的最小结果、去敏审计记录、失败记录与校验值，不包含API密钥、环境变量、真实个人身份信息、本机绝对路径或完整原始提示轨迹。

三轮同配置稳定性测试于2026年8月至9月进行，使用同一固定测试清单、主要代码版本、受测模型名称与审计模型配置；随机种子为0，并行数为2。语义审计模型为GPT-4o，`temperature=0`，API超时30秒，网络或超时异常最多重试1次。原始记录未保存可验证的服务端权重快照或系统指纹，因此这里不声称远程模型调用完全确定。更早的不同配置历史运行不属于这三轮，也未收入本公开材料。

## 1. 表2主对抗实验
- 三轮同配置完整测试的标准1500次成功绕过数分别为0、0、2；三轮审计失败阻断数和框架错误数均为0。
- 正文表2采用三轮中攻击成功率最高的一轮作为保守报告结果。该轮标准1500次中成功绕过2次，ASR=2/1500=0.13%。
- GPT-4o-mini/MIXED另有19次同配置补充复测，重复标准MIXED单元中的既有样本，不作为新增独立样本，也不计入1500次主ASR分母；19次复测中无成功绕过。
- 提供正文采用轮的1519条最小逐样本结果（1500+19）、逐单元汇总，以及两个成功绕过样本的去敏审计记录。
- 两个成功绕过分别位于GPT-4o-mini/DPI（CaseReviewTool）和Llama-3.1-70B-Instruct/DPI（PatientRecordAccess）。

## 2. 表3消融实验
- 提供完整4HDP、移除累积风险状态追踪、移除LLM语义审计、移除AST结合污点分析四种配置的结果摘要。
- 同时提供状态追踪专项配对结果和执行流筛选微基准，用于核验RQ4补充分析。执行流筛选正文所报告的捕获率、漏捕率和误捕率均对应`screening_enabled=true`；JSON中的`screening_enabled=false`仅作为关闭筛选后的对照，此时请求不再被筛除。

## 3. 表4及反馈实验
- 固定载荷审计压力测试：每种审计模型均包含118个恶意样本和34个高难度良性对照。
- GPT-4o-mini：审计绕过0，FPR=11.76%，审计失败0；GPT-4o：审计绕过0，FPR=5.88%，审计失败1。
- 有限知情配对载荷测试：每种审计模型72条审计记录，审计绕过均为0；72条为重复审计记录，不代表72个独立攻击样本。
- 反馈闭环实验：48个独立场景、133组有效重复配对，反馈组和等预算无反馈组均无经核验审计绕过。288条逐臂最小状态包含276条完成、2条审计后端失败、4条攻击者模型调用错误及6条目标判断模型调用错误；未完成记录不计为安全阻断或攻击绕过。

## 4. 失败记录
- 表4 GPT-4o固定载荷测试中的1次审计失败提供去敏后的结构化记录。
- 反馈闭环实验的2次审计后端失败以汇总说明单独列出；12条未完成执行另见`04_失败记录/反馈闭环实验_逐臂最小状态.csv`，其中不包含攻击载荷。
- 表2三轮主对抗实验和表3消融实验中均无审计失败或框架错误，因此不存在对应失败样例。

## 5. 去敏与完整性
- 表2逐样本文件只保留实验配置、样本ID、结果状态、原始行号和源文件SHA-256等核验字段。
- 两个成功绕过样本的记录对姓名、客户/患者编号等内容进行替换，并以完整的去敏摘要替代原始消息轨迹；不存在截断到半句或残缺JSON的公开文本。
- 表4审计失败样本仅保留失败类型、统计结果和去敏原因，不公开攻击载荷或原始提示内容。
- `05_校验信息/原始源文件_校验值.csv`记录核心原始源文件的逻辑来源与SHA-256，不包含本机绝对路径。
- `SHA256SUMS.txt`用于校验本包内公开文件本身的完整性。

## 6. 统计口径说明
- 主ASR只以1500次标准执行为分母；额外19次补充复测单独报告。
- “安全阻断数”并不与“成功绕过数”共同覆盖全部执行：部分对抗样本未形成成功攻击且未触发安全阻断。逐单元汇总已新增“未形成成功绕过且未触发安全阻断数”，并提供“合计校验”列，确保各单元分类之和等于执行数。
- 固定载荷审计压力测试中的“审计绕过率”与端到端ASR不是同一统计概念，按论文修订稿口径分别使用。

## 7. 表2对照结果与良性400
- `01_表2_主对抗实验/表2_无防御及提示层对照_选定结果汇总.csv`及对应的逐样本最小结果只收录论文表2选定的42个无防御、提示层对照实验单元，共4200次有效执行。每行保留结果、源CSV行号和源文件SHA-256；其他历史运行不在本目录中。
- `06_良性400/`提供400个正常任务的最小逐样本结果和摘要：394次正常放行、5次安全误拦、1次审计失败。功能保全率为394/400=98.50%；排除审计失败后安全FPR为5/399=1.25%。
- 反馈闭环的12条未完成记录分布于11组场景重复配对，因此48×3=144组潜在配对中有133组有效。运行状态和实验结果为不同统计维度，请勿将重复执行当作独立攻击样本。

运行`python scripts/verify_revision_evidence.py`可重算本目录的关键结果并核对文件哈希。引用本材料时请使用所在仓库的固定提交哈希，避免远程模型变化造成版本混淆。
