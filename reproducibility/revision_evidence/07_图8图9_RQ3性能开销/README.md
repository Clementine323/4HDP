# RQ3 图8、图9：公开统计及来源说明

本目录只补充**论文表2正文采用轮**的 RQ3 性能开销，与原仓库表2公开结果采用相同的15个“受测模型—攻击类型”标准单元（每单元100次，合计1500次）。不加入额外19次重复执行或独立的400条良性任务，也不加入未选中的历史运行。文件中的图片直接提取自相应修订稿，未重排、重新绘制或修改字体配色。

## 文件

- `图8图9_逐单元审计开销.csv`：15行实验单元的审计事件数量、单事件均值/中位数、审计LLM输入与输出Token，以及对应原始结果 CSV、RQ3 统计 JSON、审计事件 JSONL 各自的 SHA-256。哈希用于连接原始本地记录、表2已公开去敏结果及图8/图9的统计口径；**不会使未公开的原始记录自动可下载**。
- `图8图9_整体汇总.json`：对所有2925个审计事件加权得到的总体指标、统计口径和分位数定义。
- `图8_论文采用图片.png` / `图9_论文采用图片.png`：已嵌入修订稿的图8、图9原图，保留论文已有版式。

## 计算口径

1. 图8为各单元所有执行前审计事件 `audit_latency_s` 的算术平均值，不是无防御基准减法意义上的“时间开销增量”，也不是每任务端到端耗时。不同单元审计事件数量不相同，不能对15个柱高取简单平均来估计总体单事件均值。
2. 图9仅统计**审计LLM**的 `audit_token_usage.total_prompt_tokens` 与 `total_completion_tokens`，不混入受测智能体自身的 Token。各单元各100个标准对抗任务，Token柱高展示的是该实验单元的累计消耗。
3. GPT-4o-mini/MIXED 与 Llama-3.1-70B-Instruct/MIXED 未调用审计LLM，因此两组 Token 为0；GPT-4o/MIXED虽主要为快速判定，仍有4次审计LLM调用，不能误写成0。
4. 总体平均审计耗时按 `sum(单元平均耗时 × 单元审计事件数)/sum(审计事件数)`（或等价的逐事件总体算术平均）计算。中位数、P95必须使用逐事件原始耗时序列计算；在不公开含敏感上下文的逐事件原始记录情况下，本目录只发布统计结果，不声称其他人仅靠15行平均值即可独立重算总体中位数/P95。
5. P95同时列出两种常见定义：**lower-index** 为升序排列、0-based 索引 `floor((N-1)×0.95)` 所在值；**linear** 为相邻次序统计量间线性插值。正文如写“P95约5.22秒”，采用前者；若按通常的线性插值则为约5.25秒。两种差异源自分位数定义，并非实验冲突。
6. GPT-4o/MP存在单个很高的审计耗时事件（约920.32秒）；该单元均值8.56秒、中位数3.05秒，故不应把所有实验单元描述为延迟集中在3.5至5.5秒。
